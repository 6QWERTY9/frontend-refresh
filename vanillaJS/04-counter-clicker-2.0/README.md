# 📝 Техническое задание (ТЗ): Кликер с магазином улучшений (Idle-кликер)

## 🎯 1. Общее описание проекта
Проект представляет собой браузерную экономическую игру-кликер на чистом JavaScript (Vanilla JS). Игрок кликает на главную кнопку, зарабатывает очки («баланс») и покупает на них улучшения. Улучшения бывают двух типов: увеличивающие доход за один клик и приносящие пассивный доход автоматически каждую секунду. Прогресс игрока должен автоматически сохраняться.

---

## 🛠 2. Функциональные требования

### 🧱 Элементы интерфейса (HTML / CSS)
На экране должны быть четко разделены три зоны:
1.  **Информационная панель:**
    *   Текстовое поле с текущим балансом игрока (например, `"Баланс: 0 очков"`).
    *   Текстовое поле с текущим пассивным доходом (например, `"В секунду: +0 очков"`).
2.  **Игровая зона:**
    *   Главная кнопка для кликов.
3.  **Магазин улучшений (минимум 2 карточки товаров):**
    *   **Улучшение №1 («Сила клика»):** увеличивает доход от каждого ручного нажатия.
    *   **Улучшение №2 («Авто-кликер»):** запускает пассивный ежесекундный доход.
    *   *Каждая карточка содержит:* название, текущую стоимость товара, количество уже купленных штук и кнопку «Купить».

---

## ⚙️ 3. Логика и механика (JavaScript)

### 📈 Игровое состояние (State)
В коде должен быть один глобальный объект для хранения состояния игры:
*   `balance` (число) — текущие очки игрока.
*   `clickPower` (число) — сколько очков дает один клик (изначально `1`).
*   `passiveIncome` (число) — сколько очков капает в секунду (изначально `0`).
*   Цены и количество купленных улучшений каждого типа.

### 🖱 Механика главного клика
*   При нажатии на главную кнопку к `balance` прибавляется значение `clickPower`.
*   Интерфейс баланса мгновенно обновляется.

### 🏪 Механика магазина и Инфляция
При нажатии на кнопку «Купить» у любого улучшения:
1.  **Проверка баланса:** Программа проверяет, хватает ли `balance` на покупку (цена товара <= баланс).
2.  **Списание и покупка:** Если денег хватает, цена вычитается из `balance`, а количество купленного товара увеличивается на `1`.
3.  **Рост цен на 15%:** После покупки базовая стоимость этого конкретного улучшения автоматически увеличивается по формуле: `Новая_Цена = Math.round(Старая_Цена * 1.15)`.
4.  **Блокировка кнопок:** Если у игрока не хватает очков на товар, кнопка «Купить» для этого товара должна визуально становиться неактивной (свойство `disabled` или CSS-класс). Проверка доступности покупок срабатывает при *каждом* изменении баланса.

### ⏱ Автоматическое начисление (`setInterval`)
*   В игре запускается **один общий таймер** через `setInterval` с интервалом в 1000 миллисекунд (1 секунда).
*   Каждую секунду этот таймер прибавляет значение текущего `passiveIncome` к общему `balance`.
*   После прибавления обновляется текст баланса на экране и пересчитывается доступность товаров в магазине.

### 💾 Сохранение прогресса (`localStorage`)
*   **Автосохранение:** При каждой успешной покупке в магазине или при выходе/закрытии страницы текущий объект состояния (`state`) преобразуется в строку через `JSON.stringify()` и записывается в `localStorage`.
*   **Загрузка при старте:** При первой загрузке страницы игра проверяет наличие данных в `localStorage`. Если сохранение найдено, оно парсится через `JSON.parse()` и восстанавливает баланс, силу клика, пассивный доход и текущие (выросшие) цены на улучшения. Если сохранения нет — игра начинается с дефолтных значений.

---

## ⚡ 4. Технические ограничения
*   **Только Vanilla JS:** Чистый HTML, CSS и один JS файл. Никаких сторонних библиотек.
*   **Без классов:** Код пишется в процедурном / функциональном стиле, без использования конструкций `class`.
*   **Работа с DOM:** Для обновления текста на экране использовать исключительно свойства `textContent` или `innerText` (не использовать `innerHTML`).
*   **Безопасность таймеров:** Перед созданием нового интервала всегда вызывать `clearInterval`, чтобы избежать утечек памяти и ускорения таймеров при перезапусках.
