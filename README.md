# 🏖️ frontend-refresh

Репозиторий для бережного, постепенного и осознанного возвращения во фронтенд-разработку после перерыва. Главная цель — разбудить мышечную память, вернуть уверенность в синтаксисе и получать удовольствие от визуального результата, полностью исключив риск выгорания. 

---

## 📜 Программный манифест (Правила игры)

1. **Принцип минимализма:** Никаких тяжелых фреймворков (React), типизации (TS) и сложных сборщиков на старте. Только чистый фундамент: HTML, CSS и Vanilla JS.
2. **Фокус на логику и чистоту:** Дизайн и вёрстка сейчас не в приоритете. Главное — вспомнить, как связывать интерфейс с логикой на чистом JavaScript и писать понятный код.
3. **Защита от выгорания:** Никаких жестких дедлайнов и таймеров. Пишем в своём темпе.

## 🗺️ Дорожная карта возвращения (Roadmap)

### Этап 1: Чистый фундамент (Vanilla JS) [Текущий этап]

* [ ] **01-counter-clicker** — Базовый кликер: кнопки, счётчик, работа с DOM (document.getElementById).
* [ ] **02-todo-list** — Классический список задач: массивы, добавление и удаление элементов с экрана, обработка событий (addEventListener).
* [ ] **03-theme-toggler** — Переключатель тёмной/светлой темы: манипуляции с классами элементов, работа с локальным хранилищем (localStorage).

### Этап 2: Возврат к стилям (Sass)

* [ ] Подключение расширения *Live Sass Compiler* в VS Code для компиляции стилей в один клик.
* [ ] **04-interactive-dashboard** — Простая приборная панель с использованием вложенных стилей, переменных и миксинов Sass.

### Этап 3: Плавный камбэк в React & TypeScript

* [ ] Перенос одного из прошлых мини-проектов на чистый React.
* [ ] Постепенное внедрение строгой типизации TypeScript поверх готовой React-логики.

## 🏷️ Стандарты коммитов (Conventional Commits)

Чтобы история разработки была чистой и понятной, используем строгие префиксы для каждого микро-шага: 

* **feat(project-name): ...** — добавление новой логики или фичи. 

  * *Пример:* feat(counter): implement decrease logic and disable button at zero
* **style(project-name): ...** — добавление или изменение стилей (CSS/Sass), разметка HTML (без изменения логики). 

  * *Пример:* style(todo): add dark theme variables and button transitions

* **fix(project-name): ...** — исправление багов, опечаток или заклинивших функций. 

  * *Пример:* fix(theme): fix localstorage checking on page reload
* **docs(project-name): ...** — обновление документации, комментариев или JSDoc. 

  * *Пример:* docs(counter): add JSDoc types for click event handlers

* **refactor(project-name): ...** — улучшение структуры кода, переименование переменных (без изменения работы). 

  * *Пример:* refactor(todo): split massive render function into smaller helpers
